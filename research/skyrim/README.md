# Skyrim launcher diagnostic

Skyrim (Steam 489830, FAKE78005) and Blackjack reported the same SIGSYS and the same launcher digest. The underlying cause is not established; do not treat this diagnostic as a fix.

`launcher-stage-diagnostic.patch` applies to `native/wine64_main.c` from source revision `ce289425bb34acbcc98f77b4e00ac98b3c16e4bc` in the locally preserved return-wrapper source. It adds notifications and direct diagnostic logging for startup failures that can occur before the ordinary logging worker is ready. It deliberately excludes account credentials and file paths from notifications.

The isolated build succeeded using the prepared local foundation. Its eboot SHA-256 was `1ac5eb4a76f6caeb7bf8872b7e1258b021f981383d3b3177f5b03cc377d748d4`. It adds a `sceKernelSendNotificationRequest` import whose runtime binding is unverified. It has **not** been admitted, installed, or tested on the PS5. The generated manifest incorrectly identifies the enclosing workspace Git revision because the source was built from an archive; it is not reliable provenance and must be corrected before packaging.

Do not replace the installed launcher or change a runtime kit without updating and validating all applicable hashes, provenance, title identity, and ownership records. The existing Skyrim Home artwork was separately repaired; the user confirmed it appeared after a PS5 restart.

Details and evidence: `evidence/wine11-skyrim-launch-investigation.json` and `evidence/wine11-skyrim-home-icon.json`.

`admission_observer.c` is an offline, fixed-identity adaptation of the pinned Wine 11 admission observer for FAKE78005 / Steam 489830. It uses the exact same native descriptor and publication reader, nonblocking shared lease, and owner-marker checks; it does not mount, elevate, launch, repair, or write. `bash tools/test-skyrim-admission.sh` verifies the pinned upstream hashes and that this copy differs only in identity, then adapts the upstream synthetic fixture to Skyrim's title and app IDs. Its host tests cover successful observation, absent grant, busy or missing lease, owner mismatch, invalid owner mode or link count, mismatched UID, and publication mismatch; they check file bytes, metadata, inodes, and descriptor closure. The fixture is synthetic and does not represent the installed Skyrim publication.

This source has not been integrated into an app, compiled for PS5, deployed, or run on the console. A valid hardware observation requires the normal authorized data grant and actual title owner UID, plus the PS5 lock gateway; a loader running with different credentials cannot establish the title's outcome. Even a passing observation does not establish full kit integrity, stopped state, launcher execution or the cause of SIGSYS, and never authorizes installation. A refusal is scoped to admission and cannot diagnose earlier launcher stages.

`launcher-late-diagnostic.patch` is a supplemental diagnostic against the already-patched isolated source in `build/skyrim-launch-probe-source`. It adds notices for library-path truncation, default-profile refusal, prefix or executable refusal, DLL override refusal, and Zink provider failure. Patch dry-run succeeded; this supplement has not been built, admitted, or run. It inherits the unverified notification import. No notice does not prove a stage succeeded: execution or notification may fail before it is delivered.

The fixed observer compiled to a PS5 object with `bash tools/compile-skyrim-admission.sh`; no executable was linked. `admission-ui.patch` is an unapplied proposal for an isolated app build that reuses the existing explicit About > Game return check, relabels it for Skyrim and exposes fixed refusal stages. The normal app source and its Quake action remain unchanged. In an isolated staging tree only, replace the observer source with the scoped copy and apply the UI patch; do not link both copies because they export the same symbols. The patch has passed an applicability check, but has not been compiled, tested in the UI, or packaged. The app's filesystem grant verifies data accessibility, while the reader checks actual effective UID against file ownership. Whether that context matches Skyrim on hardware remains unverified.

The local PPSA77382 diagnostic candidate must not be installed: PPSA77382 is the existing Vapor test app, and the candidate does not include its Steam bridge. Replacing it would remove Vapor functionality. The archived build script is disabled. A separate PPSA77383 identity has no observed folder in the three checked console locations, but registration in app.db has not been checked; its availability and owner context are unverified.

`exclusive_publish.c` is an unintegrated filesystem prototype fixed to PPSA77383. It claims a new root with `mkdirat`, opens it without following symlinks, retains and rechecks directory identity, creates immediate child files with `O_EXCL|O_NOFOLLOW`, and applies permissions through open descriptors. It leaves partial output for inspection on failure. Host fixture tests cover existing directories/files, symlinks and replacement of the claimed root, and pass with address and undefined-behavior sanitizers. The source also compiles to a PS5 object, but has not been linked or tested there. It currently supports immediate child entries only; it is not a complete installer. It does not verify package hashes, securely transport bytes, reserve the app database identity, prevent all same-privilege interference, or authorize deployment. Live WFM installation remains disabled.

The publisher prototype now supports nested descriptors, retaining and rechecking each ancestor's device, inode and owner. The independent `candidate_verify.c` checks each of the 27 pinned package files, including the exact manifest digest, through no-symlink descriptor traversal; it is not a directory inventory check and does not reject unrelated extra entries. Host tests accept the pinned package and reject a changed binary and a symlink. Verification alone cannot bind future reads: any publisher must rehash the exact bytes it publishes and preserve source identity across verification and copying. `verify-only.elf` links the verifier and publisher primitive but its entry point only reads a fixed staging directory; it does not claim or publish a title. It is unrun on PS5. Registration and app.db collision races, transfer staging, full publisher integration, and PS5 behavior remain unresolved.

`candidate_publish.c` integrates the pinned preflight and exclusive directory publisher. It reopens and hashes each source file into memory and publishes those same bytes, creates only exclusive files, retains partial output on error, and writes `sce_sys/param.json` in a final pass. Sanitized host integration tests verify the resulting hashes and refusal of a pre-existing title; an injected staged-binary change after preflight is refused before metadata publication. The linked `publisher-UNTESTED.elf` is a write-capable prototype and must not be run without separate review of registration, staging, identity, and PS5 behavior. It does not reserve app.db or protect against every same-privilege actor; writing param.json may allow external registration.

`title_rule_owner_probe.c` is a separate offline-prepared read-only observation, not the previously admitted storage-owner probe. It checks fixed title-rule directory/list type, root owner, writable mode, single-link count and limited same-inode stability, without reading contents, writing, changing credentials or interacting with a title. `bash tools/test-skyrim-title-rule-observer.sh` passes synthetic normal, unsafe mode, hardlink and symlink cases. Its PS5 ELF was compiled but is unrun and not admitted. Results would describe the loader context and current names only, not the game/helper process or cause of SIGSYS; ancestor symlink and concurrent replacement races are not fully excluded. No console execution was performed; coordinate before any run.

`helper-stage-diagnostic.patch` is an independent source-level proposal against the preserved return-wrapper source, not a crash fix. It carries the existing helper API’s fixed internal stage, numeric error, and identity-validated status through the data-mount result. It adds those fields to buffered diagnostics and, only on bootstrap failure, makes a best-effort call to the already-enabled network logger. No paths, account data, or credentials are included. A disabled or failed network logger, a crash before the logging call, or a crash within it can still leave no record. The patch applies cleanly; `bash tools/test-skyrim-helper-stage.sh` applies it in a temporary host tree and verifies failure-stage/status propagation, UID restoration and no-request initialization. The changed data-mount and helper translation units compiled separately for PS5; the complete launcher was not rebuilt, installed, admitted, or run.

`startup-checkpoints.patch` and `pw_startup_checkpoints.h` are an independent host-tested source proposal against the unmodified preserved return-wrapper source. Copy the header into that source's `native/` directory before applying the patch; it is not included in the patch. Fixed labels surround descriptor, HID preload, library, data-mount and umask calls, using the existing network logger only when enabled. Outcomes are normalized to -1/0/1 and helper errors to a boolean; the sender preserves `errno` and ignores sink failures. Thus a data-mount return can report a helper failure even when visible-data fallback makes the overall result successful. `bash tools/test-skyrim-startup-checkpoints.sh` checks patch applicability and host-injected mount failure, successful fallback, failed/disabled sink, errno, fixed label bounds and unchanged helper call count. It does not execute the patched full launcher, model crashes, prove the PS5 logger or runtime ABI, or establish that logging has no timing effects. No connection or no checkpoint is inconclusive; the first checkpoints start after logger setup. This does not capture SIGSYS registers or syscall identity. No launcher build, package, or console installation was performed for this proposal.
